## Executive Summary

قطاع الصحة في محافظة إب هو أحد أهم القطاعات الخدمية في المحافظة، حيث تخدم المحافظة التي يبلغ عدد سكانها حوالي **3 ملايين نسمة** شبكة من المنشآت الصحية تزيد عن **416 مرفقًا صحيًا** (حسب تقرير HeRAMS 2023). يعاني القطاع من تحديات هائلة نتيجة النزاع المسلح المستمر منذ 2015، حيث تعمل **51% فقط من المنشآت الصحية بكامل طاقتها**.

يهدف هذا المشروع إلى بناء **قاعدة بيانات رقمية شاملة** لجميع المنشآت والمؤسسات الصحية في محافظة إب، تشمل المستشفيات والمراكز الطبية والعيادات والمختبرات والصيدليات وغيرها، مع نظام معلومات متكامل يمكن المواطنين والمتخصصين من الوصول إلى المعلومات الصحية بسهولة.

**المصدر**: HeRAMS Yemen Baseline Report 2023 - WHO, ReliefWeb

# المرحلة الأولى: Project Discovery

## المشكلة

1. **تشتت المعلومات**: لا توجد قاعدة بيانات موحدة للمنشآت الصحية في محافظة إب
2. **صعوبة الوصول**: المواطنون يجدون صعوبة في معرفة أقرب منشأة صحية أو التخصص المطلوب
3. **غياب التصنيف**: لا يوجد تصنيف موحد يسمح بالتحليل والإحصاء
4. **ضعف التحديث**: المعلومات الصحية قديمة وغير محدثة بشكل دوري
5. **عدم وجود تقييم**: لا توجد آلية لتقييم جودة الخدمات من قبل المستفيدين

## الحل

بناء **نظام معلومات صحي شامل** (Health Information System) لمنشآت قطاع الصحة في محافظة إب، يتضمن:
- قاعدة بيانات مركزية لجميع المنشآت الصحية
- واجهة بحث وتصفح تفاعلية
- نظام تصنيف وتقييم
- لوحة تحليل وإحصاءات
- تكامل مع الخرائط (GPS)

## القيمة المضافة

- تسهيل وصول المواطنين للخدمات الصحية
- توفير بيانات دقيقة لصناع القرار
- تحسين التخطيط الصحي في المحافظة
- تمكين المنظمات الإنسانية من تحديد الفجوات والاحتياجات
- رفع كفاءة الاستجابة للطوارئ الصحية

## Business Model

| العنصر | الوصف |
|--------|-------|
| الجمهور المستهدف | المواطنون، الأطباء، المرضى، المنظمات، الجهات الحكومية |
| مصدر التمويل | منح تنموية، إعلانات، اشتراكات المؤسسات، دعم حكومي |
| القنوات | تطبيق ويب، تطبيق موبايل، API مفتوح |
| نموذج الإيرادات | Freemium للمؤسسات، إعلانات مستهدفة، خدمات تحليل مدفوعة |

## Vision

"نحو قطاع صحي شفاف ومترابط في محافظة إب، يمكن كل مواطن من الوصول إلى الخدمة الصحية المناسبة في الوقت والمكان المناسبين."

## Mission

"بناء منصة رقمية شاملة توفر قاعدة بيانات دقيقة ومحدثة لجميع المنشآت الصحية في محافظة إب، مع أدوات بحث وتصنيف وتقييم وتحليل، تسهم في تحسين جودة الخدمات الصحية وتسهيل الوصول إليها."

# المرحلة الخامسة عشرة: Software Architecture

## Proposed Architecture: Modular Monolith with Domain-Driven Design

### Why Modular Monolith?

1. **بساطة النشر**: تطبيق واحد بدلاً من عدة Microservices
2. **أداء عالي**: لا تأخير في الاتصال بين الخدمات
3. **تطوير سريع**: سهولة الإضافة والتعديل
4. **قابلية التوسع**: يمكن تحويل الوحدات لـ Microservices لاحقًا

### Architecture Diagram

```
┌─────────────────────────────────────────────┐
│                   Frontend                    │
│  (React + Tailwind CSS + Next.js)            │
├─────────────────────────────────────────────┤
│                   API Gateway                 │
├─────────────────────────────────────────────┤
│  ┌──────────┐ ┌──────────┐ ┌──────────┐     │
│  │  Search   │ │ Facility │ │  Auth    │     │
│  │  Module   │ │  Module  │ │  Module  │     │
│  └──────────┘ └──────────┘ └──────────┘     │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐     │
│  │  Review   │ │Analytics │ │  Map     │     │
│  │  Module   │ │  Module  │ │  Module  │     │
│  └──────────┘ └──────────┘ └──────────┘     │
├─────────────────────────────────────────────┤
│       Shared Kernel (Domain Models)          │
├─────────────────────────────────────────────┤
│              Database Layer                   │
│         PostgreSQL + PostGIS + Redis          │
└─────────────────────────────────────────────┘
```

## Design Patterns

| النمط | الاستخدام |
|-------|-----------|
| Repository Pattern | فصل طبقة البيانات عن منطق الأعمال |
| CQRS | فصل القراءة عن الكتابة (للإحصائيات) |
| Unit of Work | إدارة المعاملات |
| Factory Pattern | إنشاء الكيانات |
| Observer | الأحداث والتنبيهات |
| Strategy | استراتيجيات البحث المختلفة |

# المرحلة السابعة عشرة: Security Analysis

## OWASP Top 10 Mitigations

| الثغرة | الإجراء الوقائي |
|--------|----------------|
| **Broken Access Control** | RBAC + JWT مع صلاحيات لكل دور |
| **Cryptographic Failures** | HTTPS إجباري، تشفير كلمات المرور (bcrypt) |
| **Injection** | Parameterized Queries عبر Prisma، تعقيم المدخلات |
| **Insecure Design** | Rate Limiting، التحقق من المدخلات (Zod) |
| **Security Misconfiguration** | إعدادات أمان افتراضية، إخفاء معلومات الإصدار |
| **XSS** | Content-Security-Policy، تعقيم المخرجات |
| **CSRF** | CSRF Tokens، SameSite Cookies |
| **SSRF** | قيود على الطلبات الخارجية |
| **Logging & Monitoring** | تسجيل جميع العمليات الحساسة |
| **API Security** | Rate Limiting (100 req/min)، API Keys |

## Authentication Flow

```
[تسجيل الدخول]
    ↓
[إدخال البريد/الهاتف + كلمة المرور]
    ↓
[التحقق من البيانات]
    ↓
[إصدار JWT Token (مدة: 24 ساعة)]
    ↓
[Refresh Token (مدة: 7 أيام)]
    ↓
[تخزين آمن في HttpOnly Cookie]
```

## Data Protection

| الإجراء | الوصف |
|---------|-------|
| Encryption at Rest | تشفير قاعدة البيانات (AES-256) |
| Encryption in Transit | TLS 1.3 |
| Password Hashing | bcrypt (cost: 12) |
| API Keys | مخزنة في Environment Variables |
| Secrets Management | .env + Vault |
