## 17.2 إجراءات الأمان (Security Measures)

### أ. المصادقة والتفويض (Authentication & Authorization)

| الإجراء | التفاصيل |
|---------|---------|
| **JWT Authentication** | توكنات قصيرة المدى (15 دقيقة) + Refresh Token (7 أيام) |
| **OTP Verification** | التحقق برقم الهاتف (رسالة SMS) |
| **Password Hashing** | bcrypt (cost factor 12) |
| **RBAC** | Roles: customer, restaurant_owner, driver, admin |
| **Rate Limiting** | 5 محاولات تسجيل دخول في الدقيقة |
| **Device Tracking** | تسجيل الأجهزة، إشعار عند جهاز جديد |

### ب. حماية البيانات (Data Protection)

| الإجراء | التفاصيل |
|---------|---------|
| **TLS 1.3** | جميع الاتصالات مشفرة |
| **Encryption at Rest** | AES-256 للبيانات الحساسة |
| **SQL Injection Prevention** | Parameterized queries (Prisma) |
| **XSS Prevention** | Sanitize المدخلات، Content Security Policy |
| **CSRF Protection** | SameSite cookies, CSRF tokens |
| **Input Validation** | Zod schemas لجميع المدخلات |

### ج. حماية API

| الإجراء | التفاصيل |
|---------|---------|
| **API Keys** | للتطبيقات الخارجية |
| **Rate Limiting** | 100 طلب/دقيقة لكل مستخدم |
| **CORS** | تقييد النطاقات المسموحة |
| **Request Validation** | التحقق من جميع المدخلات |
| **IP Whitelisting** | للوحة الإدارة فقط |

### د. أمن المدفوعات

| الإجراء | التفاصيل |
|---------|---------|
| **PCI DSS Compliance** | الامتثال لمعايير أمن المدفوعات |
| **Tokenization** | عدم تخزين بيانات البطاقة |
| **3D Secure** | للتحقق من المدفوعات |
| **Encryption** | تشفير جميع معاملات الدفع |

## 17.3 سياسة الخصوصية (Privacy Policy)

| البند | التفاصيل |

## 17.4 خطة الاستجابة للحوادث (Incident Response Plan)

| المرحلة | الإجراء | المسؤول | الوقت المستهدف |
|---------|---------|---------|---------------|
| **1. الكشف** | مراقبة الأنظمة (Sentry, UptimeRobot) | فريق التقنية | فوري |
| **2. التقييم** | تحديد نوع الحادث ومدى تأثيره | مدير التقنية | < 15 دقيقة |
| **3. الاحتواء** | عزل النظام المخترق، تعليق الحسابات | فريق الأمان | < 30 دقيقة |
| **4. التحقيق** | تحليل logs، تحديد سبب الاختراق | فريق الأمان | < 4 ساعات |
| **5. المعالجة** | إصلاح الثغرة، استعادة البيانات | فريق التقنية | < 24 ساعة |
| **6. الإبلاغ** | إبلاغ المستخدمين والجهات المعنية | الإدارة | < 48 ساعة |
| **7. التوثيق** | كتابة تقرير الحادث والدروس المستفادة | جميع الفرق | < أسبوع |

## 17.5 النسخ الاحتياطي واستعادة البيانات

| النوع | التكرار | طريقة الاستعادة | وقت الاستعادة المتوقع |
|-------|---------|-----------------|----------------------|
| Full DB backup | يومي | pg_restore | 30 دقيقة |
| WAL archiving | مستمر | Point-in-time recovery | 15 دقيقة |
| Static files (صور) | أسبوعي | R2/S3 restore | < 1 ساعة |
| Configuration | عند التغيير | Git + Ansible | 10 دقائق |

## 17.6 قائمة التحقق الأمني (Security Checklist)

- [ ] تفعيل HTTPS وإجبار TLS 1.3
- [ ] إعداد CSP (Content Security Policy) headers
- [ ] منع SQL Injection (parameterized queries)
- [ ] Sanitize جميع المدخلات
- [ ] Rate limiting على جميع النقاط
- [ ] JWT مع short expiry + refresh rotation
- [ ] Hashing كلمات المرور (bcrypt)
- [ ] RBAC مع أدوار واضحة
- [ ] مراقبة النشاط المشبوه (audit logs)
- [ ] اختبارات اختراق منتظمة (Penetration Testing)
- [ ] تحديث الاعتماديات أسبوعيًا (Dependabot)
- [ ] تشفير البيانات الحساسة في قاعدة البيانات
- [ ] إعداد WAF (Web Application Firewall)
- [ ] تفعيل 2FA للمشرفين
- [ ] إعداد خطة استجابة للحوادث
